# Leptos 全栈技术论坛项目需求列表

## 1. 项目目标

新增一个基于 **Leptos 全栈模式** 的技术论坛项目，目标是实现一个类似掘金的技术社区系统，包含用户端和管理端。

系统需要支持文章发布、Markdown 编辑、图片上传、评论回复、点赞、关注、消息推送、公告推送、搜索、内容管理、权限控制等常见论坛能力。

## 2. 技术选型

### 2.1 前后端框架

* 前端/全栈框架：Leptos
* 后端服务：Rust
* UI 组件/样式：DaisyUI
* 实时通信：WebSocket
* Markdown 编辑器：支持 Markdown 编辑、预览、图片上传、代码块高亮

### 2.2 基础设施

* 数据库：PostgreSQL
* 缓存：Redis
* 消息队列/事件总线：NATS
* 对象存储：RustFS，用于图片、附件等文件存储
* 搜索引擎：Elasticsearch
* 本地开发环境：Docker Compose

### 2.3 建议职责划分

* PostgreSQL：核心业务数据存储
* Redis：缓存、限流、热点数据、会话状态、临时验证码、计数缓存
* NATS：用户通知、关注推送、公告推送、搜索索引异步更新等事件分发
* RustFS：帖子图片、用户头像、公告图片、附件存储
* Elasticsearch：帖子搜索、用户搜索、标签搜索、全文检索

## 3. 用户角色

### 3.1 未登录用户

未登录用户可以：

* 访问首页
* 查看帖子列表
* 查看帖子详情
* 查看评论和回复
* 使用基础搜索
* 查看用户公开主页
* 查看分类、标签、热门内容

未登录用户不可以：

* 发布帖子
* 发表评论
* 回复评论
* 点喜欢
* 收藏帖子
* 关注用户
* 接收个人推送
* 访问管理端

### 3.2 普通登录用户

普通用户可以：

* 注册、登录、退出登录
* 修改个人资料
* 上传头像
* 发布帖子
* 编辑自己的帖子
* 删除自己的帖子
* 使用 Markdown 编辑帖子
* 上传帖子图片
* 评论帖子
* 回复评论
* 点喜欢 / 取消喜欢
* 收藏 / 取消收藏
* 关注 / 取消关注其他用户
* 接收关注用户发帖通知
* 接收评论、回复、点赞、系统公告等通知
* 查看个人消息中心
* 管理自己的草稿、帖子、评论、收藏和关注列表

### 3.3 管理员 / 运营人员

管理端用户可以根据 RBAC 权限执行不同操作：

* 管理用户
* 管理角色
* 管理权限
* 管理帖子
* 管理评论
* 管理分类
* 管理标签
* 发布公告
* 推送公告
* 处理举报
* 查看操作日志
* 查看系统统计数据

## 4. 用户端功能需求

## 4.1 首页

首页需要包含：

* 推荐帖子列表
* 最新帖子列表
* 热门帖子列表
* 关注用户动态，登录后展示
* 分类导航
* 标签导航
* 公告入口
* 搜索入口

帖子列表需要展示：

* 标题
* 摘要
* 作者
* 作者头像
* 发布时间
* 分类
* 标签
* 浏览数
* 评论数
* 点赞数
* 收藏数

列表需要支持：

* 分页或无限滚动
* 按时间排序
* 按热度排序
* 按分类过滤
* 按标签过滤

### 4.1.1 首页设计稿落地要求

首页以当前提供的 Dense Workbench 设计稿为准，不做营销页和大面积介绍区，首屏直接呈现技术论坛的浏览、筛选和导航能力。

整体布局要求：

* 顶部导航固定在页面顶部，白色背景，底部浅色分隔线。
* 顶部导航从左到右依次为：Post Forum 标识、一级导航、搜索框、发布帖子按钮、管理后台入口、通知入口、登录入口。
* 一级导航包含：首页、帖子、标签、用户、文档、活动。
* 当前导航项使用蓝色文字和底部蓝色指示条表示选中状态。
* 搜索框为浅灰圆角胶囊样式，占据导航中部主空间，placeholder 为“搜索帖子、标签、用户...”，支持搜索帖子、标签和用户。
* “发布帖子”为黑色圆角主按钮，管理后台为白底描边按钮，通知使用图标入口，登录为文本入口。
* 页面主体为左右两栏：左侧为帖子列表主区域，右侧为信息侧栏。
* 页面背景为白色，列表和侧栏卡片使用浅灰边框和小阴影或无阴影，整体保持高密度、可扫描、工作台式信息结构。
* 桌面端主体宽度应接近设计稿比例，左侧帖子区约占 70% 宽度，右侧信息侧栏约占 25% 宽度，中间保留稳定间距。
* 移动端允许改为单列展示，但不能出现横向滚动；顶部导航、筛选区、帖子行、侧栏卡片需要自然换行。

首页顶部筛选区要求：

* 左侧提供帖子流切换：最新、热门、未回复、关注。
* 默认选中“最新”，使用浅蓝底胶囊样式，旁边带下拉指示。
* 右侧提供筛选控件：所有分类、所有标签、所有时间，以及列表视图/排序入口。
* 筛选控件为白底描边圆角胶囊按钮，点击后应能展开对应筛选项。
* 关注 Tab 未登录时点击应引导登录；登录后展示关注用户动态。

帖子列表区域要求：

* 帖子列表采用表格化主题流，而不是卡片流。
* 表头列为：主题、分类、标签、回复、查看、最后回复。
* 表头使用浅灰背景和底部分隔线。
* 每条帖子为一行，行间使用浅灰分隔线；hover 时可使用极浅色背景反馈。
* 每行左侧需要展示状态标识：
  * 置顶帖使用蓝色置顶图标。
  * 锁定/规则帖使用灰色锁定图标。
  * 普通未读帖使用蓝色圆点。
  * 普通已读帖使用灰色圆点。
* 每行主题区域展示标题和一行摘要，摘要超出时截断，不撑高列表。
* 分类使用彩色小标签展示，至少包含：公告、教程、问题、经验分享、讨论、站务。
* 标签使用浅蓝胶囊标签展示，支持多个标签；标签过多时以“+1”等形式折叠。
* 回复数、查看数使用数字列对齐显示。
* 最后回复列展示回复人头像、昵称和相对时间。
* 首页首屏设计稿要求展示 12 条主题，分页文案为“显示 1-12 / 342 个主题”。
* 分页在列表底部右侧，包含上一页、页码 1、2、3、省略号、29、下一页；当前页 1 使用蓝色底。

设计稿中的首页示例主题应作为首屏内容基准：

* Leptos 0.6 发布：更快的编译、更小的体积、Signal 优化
* 新手指南：从 Axum + Leptos + SQLx 搭建全栈应用
* 站点规则与发帖规范（必读）
* 在 server function 中使用 SQLx 事务的最佳实践
* Leptos + Axum 部署到 Fly.io 的完整流程
* Markdown 渲染时如何高亮显示 Rust 代码？
* Leptos WebAssembly 包大小优化实践
* 关于 resources! 宏在条件渲染下重复请求的问题
* 使用 PostgreSQL JSONB 存储配置的方案选择
* 关于 Signals 与派生状态的性能陷阱
* Axum 中间件处理 request body 的正确方式
* 从零实现一个简单的 Leptos 组件库

右侧信息侧栏要求：

* 右侧仅展示与设计稿一致的四个信息卡片：分类、热门标签、公告、活跃作者。
* 不在首页右侧额外放置“系统功能”等设计稿未出现的卡片。
* 分类卡片展示分类名称和数量：
  * 公告：12
  * 教程：34
  * 问题：156
  * 经验分享：78
  * 讨论：45
  * 站务：17
* 分类卡片底部提供“查看全部分类”链接。
* 热门标签卡片展示标签和数量：
  * leptos：132
  * axum：98
  * sqlx：86
  * postgresql：64
  * rust：61
  * wasm：48
  * server-functions：42
  * markdown：38
* 热门标签卡片底部提供“查看全部标签”链接。
* 公告卡片展示公告标题和日期：
  * Leptos 0.6 正式发布：5 月 20 日
  * 论坛升级与搜索增强说明：5 月 10 日
  * 标签体系调整公告：4 月 28 日
* 公告卡片底部提供“查看全部公告”链接。
* 活跃作者卡片展示作者头像、昵称和回复数：
  * 张晨：1.2k 条回复
  * DreamMao：980 条回复
  * Skyline：876 条回复
  * wangxy：745 条回复
  * coderLin：612 条回复
* 活跃作者卡片底部提供“查看全部作者”链接。

视觉规范要求：

* 主色使用 Meta 风格蓝色，建议为 `#0064E0`。
* 主要文字使用接近黑色的深色，次级说明文字使用灰蓝色。
* 胶囊按钮、筛选按钮和标签需要保持圆角一致。
* 卡片圆角保持克制，接近设计稿的 16px-24px。
* 列表行高度应紧凑，优先保证一屏可扫描更多主题。
* 不使用大面积渐变、装饰性背景、营销式 hero、嵌套卡片或过多阴影。
* 图标应使用统一风格，优先使用图标库或真实图标资源；禁止用 emoji 代替核心 UI 图标。

首页验收标准：

* 桌面端打开首页时，首屏视觉结构应与设计稿一致：顶部导航、筛选区、表格化帖子流、右侧四张卡片均可见。
* 首页右侧卡片数量必须为 4 个，且顺序为：分类、热门标签、公告、活跃作者。
* 首页帖子列表必须展示 12 条示例主题，并显示“显示 1-12 / 342 个主题”。
* 首页不得出现设计稿未包含的“系统功能”侧栏卡片。
* 桌面端和移动端均不得出现横向滚动。
* 搜索、发布帖子、管理后台、通知、登录、分类筛选、标签筛选、时间筛选、分页入口需要具备可点击状态。

### 4.1.2 首页设计稿的系统支撑要求

为保证首页不是静态样式稿，系统需要提供完整的数据、权限、统计和状态能力，支撑 `4.1.1` 中的所有交互与展示。

首页数据聚合要求：

* 首页必须支持一次性获取首屏所需数据，建议提供首页聚合查询能力，例如 `GET /api/home` 或等价的 Leptos Server Function。
* 首页聚合数据至少包含：帖子列表、分类统计、热门标签、公告列表、活跃作者、当前用户登录态、当前用户权限、当前筛选条件、分页信息。
* 首页聚合接口需要支持 SSR 首屏渲染，避免首屏先空白再分批加载所有模块。
* 侧栏数据允许使用缓存，但接口返回结构必须稳定；部分侧栏统计失败时，主帖子列表不能整体不可用。
* 首页首屏需要支持开发环境种子数据或 mock 数据，能稳定复现设计稿中的 12 条主题、分类数量、标签数量、公告和活跃作者。

帖子列表查询要求：

* 帖子列表必须支持 `latest`、`hot`、`unanswered`、`following` 四种 Tab，对应首页的“最新、热门、未回复、关注”。
* 列表查询必须支持分类、标签、时间范围、排序方式和分页参数。
* 查询参数需要能映射到浏览器 URL，建议使用 `tab`、`category`、`tag`、`time`、`sort`、`page`、`page_size`。
* 默认分页大小为 12，首页第一页必须能返回 `page=1`、`page_size=12`、`total=342`、`total_pages=29` 这类分页元数据。
* 热门排序需要有可解释的热度分数，至少综合发布时间、回复数、浏览数、点赞数或收藏数。
* 未回复 Tab 只展示回复数为 0 且状态为公开的帖子。
* 关注 Tab 仅对登录用户返回关注用户发布或参与的帖子；未登录用户访问时返回需要登录的状态，前端引导登录。
* 列表查询只返回公开、未删除、未下架的帖子；管理员预览或管理端查询需要使用独立权限接口。

帖子行数据要求：

* 每条帖子必须返回足够渲染表格行的数据，包括：帖子 ID、标题、摘要、分类、标签、回复数、查看数、最后回复人、最后回复时间、置顶状态、锁定状态、已读状态、是否有新回复。
* 分类数据包含分类 ID、名称、颜色标识和排序值，支持首页展示不同颜色的小标签。
* 标签数据包含标签 ID、名称和排序值；当标签超过设计稿可展示数量时，前端根据返回数量折叠为 `+1` 等形式。
* 最后回复数据包含用户 ID、昵称、头像 URL 和相对时间所需的原始时间戳。
* 置顶帖和锁定帖必须由后端状态字段驱动，不能依赖标题文案判断。
* 已读/未读状态需要基于登录用户的阅读记录或最后访问时间计算；未登录用户可使用默认未读策略或不展示个性化已读状态。
* 帖子摘要需要由后端提供安全纯文本摘要，去除 Markdown、HTML 和图片，避免前端重复解析正文。

侧栏模块支撑要求：

* 分类卡片需要基于分类表和公开帖子数量统计生成，支持分类颜色、排序、启用/停用状态。
* 热门标签卡片需要基于标签使用量或近期活跃度生成，至少支持返回前 8 个标签及数量。
* 公告卡片需要从已发布、未过期公告中返回最近或置顶的 3 条，包含标题、发布日期、跳转链接和排序权重。
* 活跃作者卡片需要基于周期统计生成，至少支持按近 30 天回复数排序，返回前 5 名作者的头像、昵称和回复数。
* 侧栏四个模块的“查看全部”链接需要有对应页面或路由承接：分类页、标签页、公告页、用户/作者榜单页。

搜索与导航支撑要求：

* 顶部搜索需要支持帖子、标签、用户三类对象，搜索结果页需要能识别来源类型。
* 搜索入口的 placeholder 固定为“搜索帖子、标签、用户...”，查询提交后进入搜索结果页并保留关键词。
* 发布帖子按钮点击后，未登录用户进入登录流程，登录用户进入发帖页。
* 管理后台入口需要根据用户权限控制可访问性；前端可以展示入口，但后端管理接口必须校验 RBAC。
* 通知入口需要支持登录态判断；未登录用户点击时引导登录，登录用户展示消息中心或通知抽屉。

计数与一致性要求：

* 回复数在评论发布、删除、审核通过或下架时更新。
* 查看数允许异步累计和缓存写回，但列表展示需要能返回近实时近似值。
* 最后回复人在新增评论或回复后更新为最新有效回复人；评论被删除或下架后需要回退到上一条有效回复。
* 分类帖子数、标签使用数、活跃作者回复数需要通过事件或定时任务更新，避免每次首页访问都做高成本全表统计。
* 帖子创建、更新、删除、下架、评论变更、标签变更、公告发布后，需要触发缓存失效或异步刷新。
* 搜索索引需要覆盖帖子标题、摘要、正文、标签、分类和作者字段；内容变更后需要异步更新索引。

管理端支撑要求：

* 管理端需要支持设置分类颜色、分类排序、分类启用状态，保证首页分类卡片和帖子行分类标签可配置。
* 管理端需要支持标签合并、标签排序、标签禁用和热门标签统计查看。
* 管理端需要支持帖子置顶、取消置顶、锁定、解锁、下架、恢复，保证首页行状态可运营。
* 管理端需要支持公告发布、置顶、撤回、生效时间和失效时间配置，保证首页公告卡片可运营。
* 管理端需要支持用户头像、昵称、封禁状态和作者活跃数据查看；被封禁或注销用户不应出现在活跃作者榜单中。

性能与容错要求：

* 首页接口 P95 响应时间目标不超过 300ms；缓存未命中时不超过 800ms。
* 首页列表查询必须避免 N+1 查询，分类、标签、最后回复人和作者信息需要批量加载。
* PostgreSQL 需要为帖子状态、分类、最后回复时间、创建时间、回复数、查看数、热度分数、帖子标签关联建立必要索引。
* Redis 可缓存热门标签、分类统计、活跃作者、热门帖子和浏览数计数。
* 首页在侧栏模块为空时需要展示空状态，不得影响帖子列表渲染。
* 首页在筛选无结果时需要展示空列表状态，并保留当前筛选条件，允许用户清空筛选。

首页系统验收标准：

* 首页聚合接口或 Server Function 的返回字段必须覆盖设计稿所有可见内容，不允许前端硬编码业务数据来满足验收。
* 使用种子数据启动后，首页能稳定展示设计稿中的 12 条主题和四个侧栏模块。
* 切换最新、热门、未回复、关注时，URL、查询参数、列表内容和空状态符合对应规则。
* 分类、标签、时间筛选和分页能组合使用，并能保持刷新后状态不丢失。
* 新增评论后，目标帖子的回复数、最后回复人、最后回复时间和未读状态能被首页正确反映。
* 管理端修改分类颜色、公告发布状态、帖子置顶/锁定状态后，首页展示能在缓存刷新后正确更新。

## 4.2 帖子发布与编辑

用户登录后可以发布帖子。

帖子字段包括：

* 标题
