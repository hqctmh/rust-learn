# Turn Store 页面 UI 优化设计

## 目标

把现有深色渐变聊天页改造成方案 2 的双栏编辑器界面：主区域服务于流式对话，右侧浅薄荷色检查器服务于 SSE 运行事件。页面继续面向调试 Agent/SSE 的开发者，不改变现有 API、请求体、会话复用或停止接收语义。

视觉目标以 [选中方案](assets/2026-07-10-turn-store-ui-option-2.png) 为准。

## 视觉系统

- 页面使用纯白画布、黑色文字、`#e6e6e6` 细分隔线，不使用渐变和投影。
- 主按钮为黑底白字胶囊；次要按钮为白底黑字胶囊并带细边框。
- 右侧检查器使用浅薄荷色 `#c8e6cd`；用户消息使用浅紫 `#c5b0f4`；Agent 回复使用奶油色 `#f4ecd6`；运行中的小状态点使用绿色。
- 字体采用现有系统无衬线字体栈，技术标签和事件名使用等宽字体，避免新增网络字体依赖。
- 桌面端以 1440×1024 为主要设计基准，正文保持舒适阅读宽度。

## 页面结构

### 顶栏

左侧显示技术眉题和 `Turn Store`，中间显示 Conversation 短 ID 与运行状态，右侧保留“新对话”黑色胶囊按钮。尚未创建会话时，中间显示“尚未创建会话”。

### 主对话区

桌面端占可用宽度约三分之二。空状态只显示开始提示，不同时展示示例消息；发出首条消息后切换为消息流。用户消息靠右使用浅紫色块，Agent 消息靠左使用奶油色块。流式光标、错误状态和自动滚动语义保持不变。

### 运行检查器

收到第一个运行事件后显示右侧检查器。事件按时间顺序呈现为轻量时间线，包含时间、事件名和精简 payload；`text` 事件只显示增量摘要，避免长文本淹没检查器。检查器可折叠，折叠状态同步到 `aria-expanded`。

### 输入区

输入区固定在主对话列底部，与页面表面直接衔接，不做悬浮卡片。上层是可自动换行的输入框，下层依次为输出模式、Conversation 状态、“停止接收”和“发送”。流式期间继续禁用输入、模式和新对话，并显示“停止接收”。

## 状态与交互

1. 初始状态：主区显示空状态，检查器隐藏，输入区可用。
2. 提交消息：空状态消失，用户消息与 Agent 流式消息出现，发送按钮禁用。
3. 收到事件：创建或更新右侧时间线；`turn_created` 更新 Conversation ID。
4. 正常结束：移除流式光标，恢复输入控件，检查器保留供复盘。
5. 用户停止：停止浏览器接收，保留当前内容，并明确提示服务端仍会完成处理。
6. 错误：Agent 消息使用浅珊瑚色错误样式，检查器追加错误事件；控件恢复可用。
7. 新对话：清空 Conversation ID、消息和事件，回到初始状态。

## 响应式规则

- `>= 960px`：主对话区与右侧检查器并排，检查器宽度约 360–400px。
- `< 960px`：检查器变为输入区上方的可折叠整行面板，主对话区占满宽度。
- `< 640px`：顶栏压缩为两行；Conversation 状态移入次行；输入区操作按钮保持可点击尺寸且不横向溢出。

## 实现边界

- 修改范围限于 `turn-store/static/index.html`、`styles.css` 和必要的 `app.js` DOM 渲染。
- 复用现有 SSE 解析、请求结构、会话状态和按钮行为。
- 不修改 Rust 路由、数据库、Redis、mock agent 或 API 契约。
- 不新增前端框架、图标包或构建步骤。

## 可访问性与验证

- 保留语义化标题、表单标签、`aria-live` 和键盘发送逻辑。
- 所有按钮具备清晰的 hover、focus-visible、disabled 状态；正文与背景满足可读对比度。
- 运行现有 `node --test static/sse.test.mjs`，确保 SSE 解析未回归。
- 在浏览器验证初始、流式、完成、停止、错误和新对话状态，并检查 1440px、960px、640px 三档布局。
- 实现后把选中方案与相同视口的页面截图并排比较，修正间距、字号、边框、色块和响应式偏差。
